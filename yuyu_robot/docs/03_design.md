# 对需求中冲突参数的处理

1. **ROS 2 命令**：使用 `std_msgs/msg/String`、`ros2 topic pub`、`ros2 launch` 和 colcon；不用 ROS 1 rostopic/roslaunch。
2. **防摔来源**：水平 360° 雷达的无穷远回波可能只表示前方没有墙，不能当作桌沿。四个下视 Range 才观察桌面是否仍在下面；顶部雷达、低位前后测距、已知边界共同补充保护。任一必需传感器或里程计过期则停止。
3. **速度**：半径 0.025 m、轮速 1 rad/s 给出 0.025 m/s 上限。导航/舞蹈用 0.02 m/s，组合转弯也等比限幅，不保留互相矛盾的 0.15/0.2 m/s。
4. **模型落地**：主体中心从 0.05 m 调到 0.09 m，让 10 cm 高外壳离桌面 4 cm，不由外壳承重。轮子和万向轮碰撞半径不缩小，壳体碰撞每边内缩 2 mm。短腿是固定外观，没有接触碰撞。
5. **宽度**：16 cm 指主体，耳机外扩后约 18.4 cm。导航用 0.115 m 保守包络半径；不能只把膨胀半径设为 0.05 m 就忽略本体半径。当前膨胀半径 0.16 m，约为包络加 4.5 cm 间距。
6. **边缘动作**：先阻止向外运动、取消导航/舞蹈；后方下视与测距安全才退回，再转向。不会先在桌沿旋转，也不保证每次强行退足 0.2 m；空间或传感器不满足则停车。
7. **唯一控制出口**：键盘、导航、行为、舞蹈分别发布原始速度。`velocity_mux` 经过新鲜度、方向、测距、边界与轮速检查后，独占 `/cmd_vel`，由差速控制器消费。外部程序不要直接向 `/cmd_vel` 发布。
8. **导航目标**：`/nav_goal` 用于观察，真正执行由 `NavigateToPose` action client 完成。导航生命周期、BT navigator、恢复行为与平滑器均启动，取消旧目标有代次校验。
9. **地图边界**：`/desk_map` 是从世界几何生成的已知地图，不宣称是扫描建出来的。SLAM 在启用时更新 `/map` 和 map→odom；导航成本图依靠已知桌沿/物品及实时激光。15 cm 高雷达看不到 3 cm 笔盒，所以不能只依赖 SLAM 地图。若改桌子或物品位置，需同步修改地图生成器、轨迹碰撞检查和边界参数，再生成资源与验收。
10. **表情呈现**：Gazebo VisualPlugin 在图形客户端的渲染阶段把 `/face_image` 贴到屏幕。RViz 的 RobotModel 不执行 Gazebo 插件，动态脸显示在 RViz 的 Face 图像面板；不要把两者混为一谈。无 GUI 模式只有图像话题，不会生成可见屏幕窗口。
11. **中文字体**：Pillow 默认字体没有可靠中文覆盖，因此显式使用 Noto CJK；缺失时提示安装，避免出现一堆方框。
12. **语音范围**：espeak 是本地基础 TTS，中文自然度有限，需要虚拟机声卡正常。`audio:=false` 用同一文字链路测试。安静状态会清空队列并终止当前进程，不只是给下一条声音静音。
13. **造型功能边界**：当前没有尾巴、关节腿或俯仰机构，不能通过一张 curious 表情让真实刚体前倾。若后续增加关节，需要同步惯量、碰撞与控制器。

14. **微型轮物理控制**：Gazebo 将装饰和传感器固定部件合并进主刚体，保留 ROS 中的原有 TF；避免许多小惯量约束导致数值发散。轮子使用速度 PID 力矩闭环，物理时间步为 1 ms；直接设置轮子瞬时速度不能保证转向负载下的实际轮速。
15. **坐标系一致性**：完整演示中的已知桌沿、物品、舞蹈路线和导航目标都在 map 中。防护和舞蹈使用 TF 的 map→base_footprint，并检查位姿新鲜度；odom 用作轮速/里程与短距离相对反馈。验收导航目标时也比较 map 位姿，不能用 odom 数值直接和 map 目标相减。
16. **SLAM 场景**：原始桌面矮物品不能为顶部水平雷达提供足够特征。启用 SLAM 时使用 desk_slam.world，桌外四片半透明标定背景提供轮廓；使用原始 desk.world 时可关闭 SLAM，先验证已知地图与仿真里程计模式。标定板在桌外，桌沿防护仍由下视传感器负责。
17. **测距兼容**：Gazebo 的无回波有时写成 float32 最大有限值，Humble 的 Python Range 边界断言会拒绝它。range_adapter 使用原始 CDR 接收，将这个无回波值规范为正无穷后再标准反序列化。公开的 /cliff 和 /proximity 保持 sensor_msgs/Range，原始数据位于 /raw 下。
18. **人工接管**：键盘重复发送的空闲零速度不拥有自动控制优先级；非零手动指令会取消导航或舞蹈，随后按键停止也不会让旧导航自动恢复。想恢复自动动作，应重新发文本指令。

尺寸修改要成组更新：改轮径/轮距时，同步控制器 YAML、速度仲裁的轮子参数；改整机包络时，同步 Nav2 半径和舞蹈几何检查；改下视安装高度时，同步落差阈值。xacro 参数化并不意味着任意改尺寸后控制与防护仍自动适配。当前提供的是经过同一组参数配置的默认模型。

核心状态为 IDLE / NAVIGATING / INTERACTING / DANCING / FLEEING；每次命令先取消旧动作，静音/停止/防护优先。并不是必须按箭头依次经过全部状态。

桌面空间狭小，旋转与平移都按真实轮速执行。默认心形会缩小到能容纳的尺寸；跟踪误差为当前目标航点距离，而非已经通过外部真值系统评估的轨迹 RMS 误差。
